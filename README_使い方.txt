TrickLog v1.0 試作版
===================

■ 何ができる？
・iPhone / Android / PC のブラウザで使う、練習記録用Webアプリ（PWA）
・最初から1Aフリースタイル用の13項目（ウォーミングアップ、2分通し×2、山場、A/B/C）を収録
・練習中に○成功／×失敗をタップして試行数・成功率を計算
・無音音ハメは技成功とタイミングを分けて記録
・通し練習は技ごとに○／△／×を記録
・途中終了、一時中断、履歴、JSONバックアップ
・メニューの新規追加、削除、編集、順番変更、目標回数変更
・メニューだけJSONファイルに書き出して友人へ渡せる

■ 友人にも使ってもらう方法（推奨）
以下のファイル一式をHTTPS対応の静的Webサイトに公開してください。
ChatGPTの利用も、アプリを動かすためのログインも不要です。

【GitHub Pagesの例】
1. GitHubアカウントで新しい「Public」リポジトリ（例 tricklog）を作る。
2. 本ZIPの中身（index.html / app.js / styles.css / sw.js / manifest.webmanifest / iconsフォルダ）を
   リポジトリの一番上（root）にアップロードしてコミットする。
3. Settings > Pages > Build and deployment > Deploy from a branch を選ぶ。
4. Branch を main、Folder を /(root) にして Save。
5. GitHub Pagesに表示されたURL（例 https://ユーザー名.github.io/tricklog/）をスマホや友人に共有。
※ 公開リポジトリではアプリのコードが公開されます。技名など公開したくないデータは初期メニューへ含めないでください。
※ GitHub Pages の設定UIは変更されることがあります。

【スマホのホーム画面に追加】
・iPhone：SafariでURLを開く → 共有 → ホーム画面に追加 →（表示されれば）Webアプリとして開くをON → 追加。
・Android：ChromeでURLを開く → メニュー（︙）→ アプリをインストール、またはホーム画面に追加。
・初回のオンライン閲覧後、PWAのファイルが正常にキャッシュされていればオフラインでも利用できます。
・インストール不要でURLからも使えます。

■ 練習中の操作
1. 「練習」で項目を順番にタップしながら進める。
2. 回数制は1回試すごとに「○ 成功」または「× 失敗」。取り消し可能。
3. 山場の音ハメは技（成功/失敗）とタイミング（合った/早い/遅い/判定不能）を選び「この1回を記録」。
4. 2分通しでは評価する技ごとに○/△/×、音ハメ、途中停止を記録。
5. 一時中断は再開可能。「今日はここで終了」でその日を履歴に残せる。
6. 「全メニュー完了」は各項目が入力済みのとき有効。
7. 翌日は「履歴・共有」→「新しい練習日を開始」。

■ メニューを編集するには
1. 「メニュー」タブで各項目の「編集」を押す。
2. 分類・技名・記録方式・目標回数を変更できる。
3. 「上へ」「下へ」で順序変更、複製・削除も可能。
4. 下の「項目を追加」で新しい技を追加する。
5. 「通し」は評価する技を『Part2 | 技の名前』のように1行ずつ登録する。
6. 「メニュー共有用に書き出す」でJSONを保存。友人は「メニューを読み込む」で使える。
7. メニューの編集は『次に開始する練習日』から反映。進行中の練習は元のメニューのまま。

■ データ保存と注意
・練習記録は各端末のブラウザ内に保存。外部サーバーへ練習結果を送信しません。
・同じURLでも友人とあなたの記録は別々。異なる端末間の自動同期はありません。
・ブラウザのデータ消去、アプリ削除、端末の故障などで履歴が消えることがあります。
・「履歴・共有」→「全データをバックアップ」を定期的に使用してください。
・友人と共有するのは「メニューを共有」。全バックアップは履歴を含むので共有時は注意。
・PWAとしてのオフライン動作は、HTTPS公開後に一度オンラインで読み込む必要があります。
・「TrickLog_単体お試し.html」はPC等で試すための単一HTML版。スマホでの継続利用はPWA公開を推奨。
・本アプリは試作版です。実機でのiPhone/Android動作やApp Store/Google Playの審査を保証するものではありません。
・サーバー側アカウント、クラウド同期、複数人の記録比較、通知などは未実装です。

■ アプリ更新
更新したファイルを同じURLに上書きアップロードしてください。
sw.js の CACHE 名を変更すると、オフラインファイルの更新を促せます。
既存データの仕様を大幅変更する際は、事前にJSONバックアップを取ってください。
